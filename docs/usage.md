# 功能与使用手册

这份是给**用**的人看的：有什么功能、在哪儿点、怎么配。
想了解内部实现看 [architecture.md](architecture.md)，想加功能看 [extending.md](extending.md)。

---

## 一句话

把 DSH 的历史会话变成**可检索的长期记忆**：关键词 → 摘要 → 原文三层索引，不遗忘、可展开到原话；每个会话的「存」和「读」由你单独决定。

---

## 四个核心概念

### ① 数据分两层

| 层 | 里有什么 | 用来干什么 |
|---|---|---|
| **记忆层** | 摘要、关键词索引，**只包含人和助手的对话** | 联想、检索、关键词榜 |
| **归档层** | 全部事件原文，**包括工具调用和结果** | `memory_search` 全文搜、展开原文时看证据 |

工具输出不进记忆层，是故意的：它们占体积又没区分度（真实数据里 `tool-result` 曾出现在 88% 的摘要里）。但它们**没有丢**，搜得到。

### ② 「存」和「读」是两个独立开关

| 开关 | 作用 |
|---|---|
| **存** | 这个会话的话要不要进记忆库 |
| **读** | 这个会话能查出哪些记忆 |

两者互不影响。典型用法：「这个会话我不想让它记录我说的话，但它可以用别的记忆来回答我」→ 存=不存，读=全库。

**默认两个都是关的**。装好之后必须你自己打开某个会话，它才会开始记、开始查。

读的取值：

| 值 | 含义 |
|---|---|
| 关 | 不读任何记忆 |
| 仅本会话 | 只读自己这个会话 |
| 全库 | 读所有已入库的会话 |
| 标签：xxx | 只读**带这个标签**的会话（可多选组合） |
| 继承 | 跟随工作区默认 / 全局默认 |

### ③ 标签

给会话打标签（一个会话可以有多个），然后读策略里就能"读所有带某标签的会话"。

比「分组」灵活：一个会话既聊 Obsidian 又做方案，不用二选一。

**怎么用按标签读**（三步）：

1. 给几个会话打上**同一个标签**：行末 `+标签` → 输入名字 → 回车
2. 在其中一个会话的「读」下拉里选 `标签：那个名字`
   —— 下拉里的标签选项来自全库已有的标签，所以第 1 步做完就会出现在这里
3. 选完之后，这一行下面会出现一排标签勾选：**点一下加入、再点一下去掉**，
   可以同时勾多个（存成 `tags:A,B`，读的就是「带 A 或带 B」的会话）

> 如果某个标签下一个会话都没有，按它读会得到**空结果**（不会退回读全库）。

### ④ 置顶

把一段内容钉成**常驻记忆**，不用靠检索碰运气。

三种来源：

| 来源 | 怎么选 | 适合 |
|---|---|---|
| 单条消息 | 点一条 | 钉一句话（"叫我鱼"） |
| 消息区间 | Shift + 点 | 钉一段对话原话，能核对 |
| 整条摘要 | 来源切「整条摘要」，点一条 | 钉某个结论 |

三种模式：

| 模式 | 什么时候注入 | 建议 |
|---|---|---|
| **按需命中**（默认） | 本轮话题相关才注入 | 大多数情况 |
| 常驻 | 每轮都注入 | 铁律、称呼、固定偏好 |
| 仅手动 | 只有模型调 `memory_pin` 时读 | 很少用但重要 |

总预算默认 **1500 字**（`pinBudget`），超了按顺序截断并注明还剩几条——不会把上下文挤爆。

> 置顶受「读」约束：当前会话读=关时，**一条置顶都不注入**（全静默）。

## 七个页面

设置 → 记忆库。

### 概览

- 规模：会话数 / 事件数 / 摘要数 / 关键词数 / 库体积
- 运行期开关：「主动联想」可以随时关掉（关掉后不再自动提示，但 `memory_recall` 工具仍可用）
- 「立即扫描」：手动触发一次增量导入

### 会话

按工作区分组，每行一个会话：

```
标题                              时间        id     入库   存      读            🏷标签
OpenClaw 呀，最近挺火              11-26 01:49 844abb  5/5  [继承▾] [仅本会话▾]  [obsidian×] [+标签]
```

- **标题** = 用户真说的第一句话（自动跳过人设卡、runtime context 这类注入内容），鼠标悬停看完整内容和入库条数
- **时间** = 最后活动时间，标题重复时靠它区分
- **入库** = 真正进了记忆库的事件数；显示「未入库」说明被「不存」挡住了
- **状态点**（右上角）：○ = 默认（不存不读），● = 已打开存或读；悬停看具体是哪个
- 每行分两行：上行是标题/时间/状态点，下行是 id/入库数/存/读/标签
- 工作区那一行有**默认策略**，改它等于改整个工作区的默认值
- 读选了「标签：xxx」之后，行里会出现标签勾选区，**点一下加、再点一下去掉**，可以多选组合

### 关键词

自动从对话里挖出来的主题词。

顶部筛选：
- **全部 / 只看中文 / 只看英文**
- **不限字数 / 2 字 / 3 字 / 4 字** ← 想找完整词组就用它
- **看哪个会话** ← 想知道"这个会话在聊什么"就用它。全库榜看不出单个会话的主题

> 为什么需要词长筛选：3/4 字的词（`人格卡`、`关键词`、`运行日志`、`训练数据`）
> 出现次数天然比 `记忆`、`消息` 这种 2 字词少，按有用度排序时会被压在后面。
> 点「3 字」「4 字」才能直接看到它们。

列表三列：

| 列 | 含义 |
|---|---|
| **关键词** | 挖出来的词 |
| **出现次数** | 有多少**条不同内容**里出现过它（原来叫 `df`，缩写看不懂，已改中文） |
| **连接度** | 它和其他词一起出现的密集度。越高越像工具名或路径前缀，可以考虑屏蔽 |

> 「出现次数」按**不同内容**统计，不是按摘要条数。同一段话（人格卡、同一份提示词）
> 出现在多个会话里只算一次 —— 否则 50% 的重复摘要会让常见词的次数虚高，
> 检索时被误判成噪声词过滤掉。

每个词可以：屏蔽（不再参与联想）、加权（填数字，越大越优先）、恢复。

**榜单里出现的都是「真词」**：系统会统计词的边界（互信息 + 左右熵），
把 `键词`、`格卡`、`件夹` 这种跨界碎片挡在外面。摘要少于 80 条时统计量不可靠，
会自动退回显示全部 2 字词（和以前一样）。

**「现在开始应用补丁：」这类过程预告不进索引**：助手在调工具前说的过渡语
会被单独生成摘要（工具调用切出新的 turn），但它没有任何检索价值。
这类碎片仍能在会话页展开看到，只是不会被联想到。有用户发言的短消息一律保留。

### 置顶

上半部分是已钉的列表（可切模式、可删），下半部分是新增：

```
从会话 [工作区 · 聊 obsidian ▾]   来源 [消息（可选用区间） ▾]
```

选 `消息` → 列出该会话的消息，点击选单条，Shift+点选区间；
选 `整条摘要` → 列出该会话的摘要，点一条。

**「只看对话」**：勾上后只显示人和助手的发言，滤掉工具调用和结果。挑置顶内容时一般都用它 —— 工具输出太长太吵。

**选中后下面会出现预览区**：显示「已选 N 条 · 共 M 字」和每条全文，直接核对内容再钉，不用去别处找。

填标题 → 选模式 → 「置顶这段」。

### 联想

**这是"我发消息到底有没有联想到东西"的核对页面。**

为什么需要它：注入到系统提示的〔记忆提示〕**界面上看不到**，只有模型能看到。所以这里把每次联想的审计记录摊开。

每行一条记录：

```
时间          你说的话                  命中（想到的摘要）                    注入  耗时
11-26 07:01  我怎么验证联想到了...     继续。先打包，再装进一个全新的临时…    +1    12ms
11-26 06:56  onmatch吧                 无                                    —     1ms
```

| 列 | 含义 |
|---|---|
| **命中** | 联想到的摘要**标题**（悬停看全部命中项、各自相关度、属于哪个会话；`✓` 标出真注入了的那几条） |
| **注入** | `+N` = 真的注入了 N 条；`—` = 没注入 |
| **耗时** | 这条消息的联想耗时（正常 1~40ms） |

> 多条命中时只显示第一条的标题 + `+N`，其余在悬停里。
> 0.4.14 之前这里显示的是 `#5039` 这种内部编号，看不懂，已改。

#### 「为什么」按钮：看一次联想是怎么算出来的

每行最右边有个「展开」。点开显示三块（0.6.0 起）：

```
查询拆成 4 个词 · 进入打分 4 个 · 词库共 383 条内容 · 阈值 0.35
参与打分   新开 31%   开一 29%   一个 18%   个ta 22%
被挡掉     tab（词库里没有）
分数构成   ✓ 开工。先做数据层：标签表 + 读策略支持标签。（续 1）
              词命中 0.41 · 扩散 +0.08 · 长度降权 ×0.82
              命中：新开/一个（620 字）
```

| 块 | 看什么 |
|---|---|
| **参与打分** | 你这句话被拆成哪些词、各自在总分里占多少。百分比高的词决定了结果 |
| **被挡掉** | 哪些词没参与，以及原因：词库里没有 / 被屏蔽 / 过于常见 |
| **分数构成** | 每条命中怎么得分的：词命中多少、扩散蹭到多少、长度降权打了多少折、命中哪几个词 |

**怎么用它排查**：

- 联想不准 → 看「分数构成」里的**扩散**。如果 `扩散` 占比大而 `词命中` 很小，
  说明这条是"蹭"上来的（通过共现代词进来的），不是真命中
- 长摘要总占位 → 看 `长度降权 ×0.xx`。乘得越狠说明降权越强，如果还是排第一，
  说明它词命中确实高
- 某个词明明有却搜不到 → 看「被挡掉」，可能被判定成"过于常见"了
- 完全没有命中 → 看「参与打分」是不是空的。空的话说明你这句话的词都不在词库里

> 0.6.0 之前的记录没有诊断信息，展开会提示「早期记录无诊断」。想看得用新对话。

`—` 的原因通常是：那句话太短或太泛（"onmatch吧"、"建议我这样吗"），没有词能过 `hintThreshold`（默认 0.35）；也可能被 `hintCooldownMin` 冷却过滤了。

顶部可以：
- 按**会话**筛选
- 「只看注入成功」——过滤掉没命中的，只看真起作用的

> 注意：命中 ≠ 模型一定用上。注入的是「标题 + 日期 + id」，模型自己判断相不相关。

### 记忆卡

**看 surfcore 的记忆，全程只读 —— 不会修改 surfcore 的任何数据文件。**

surfcore 把记忆存在 ~/.dsh/surfcore/characters/<角色>/memory/，分两份：

- **主卡**（`memory-card.json`）：日常加载的那份，会被衰减
- **全量档案**（`memory-card-full.jsonl`）：只存档，包含已经掉出主卡的那些

顶部四个数字：

| | |
|---|---|
| **在主卡里** | 当前还活着的记忆条数 |
| **已被遗忘** | 主卡里没了、但全量档案还留着的 |
| **衰减过** | 被降过清晰度的累计条数 |
| **累计进过** | 历史上进过卡的总数 |

**两种读法**（自己选）：

- **现读文件**（默认）—— 每次打开都直接读 surfcore 的文件，永远最新，但不落库
- **镜像入库** —— 读进自己的库，能搜索、能和其他数据对照；有「重新同步」和「清空镜像」

**筛选**：全文搜索、按类型筛、**「只看它忘掉的」** —— 这是这个页面最有用的一处：surfcore 按自己的遗忘曲线跑，但档案里其实还留着，你能看见它忘了什么。

**条目默认折叠**，点一行展开正文、标签、重要原因。

**这些内容不参与关键词联想。** surfcore 记的是 QQ / B站 那边的事，词汇和口吻跟 DSH 会话不是一路，混进关键词库会污染召回。所以它单独放在一张表里，自动联想永远查不到它 —— 只有你明确让我查「surfcore 记忆 / 记忆卡 / QQ 记忆 / B站记忆」时才会去翻（走 `memory_surfcore` 工具）。

**没装 surfcore 也不会报错**：这个页面会显示「没有找到 surfcore 记忆卡」并给出找过的位置，其他功能一切照常。

标了 `private` / `sensitive` 的记忆默认遮住正文，点「显示内容」才展开。

### 运维

| 功能 | 什么时候用 |
|---|---|
| **备份** | 动手前想留个后悔药。产出一个带时间戳的单文件，放在数据目录下 |
| **按当前内容范围重建** | 改了「保存哪些内容」之后，让老摘要按新规则重算（约 3 秒；**会按当前策略过滤**） |
| **全部关掉（不存/不读）** | 清掉历史遗留的所有设置，回到一个都没打开 |
| **数据目录** | 迁移到别的磁盘。迁移成功会记住新路径，重启后自动用 |
| **词表（真词）** | 看当前认出多少个真词，或手动重新发现（会连带重建索引） |
| **词向量（实验性）** | 用共现统计学词向量。**不参与检索**，只是一个备用实验 |
| **重建关键词索引** | 改了挖词阈值，或词库被污染了 |
| **导出 JSONL** | 备份 / 迁移到别的工具 |

**除了「导出」和「备份」，其余点下去都会先弹确认框，看清再点。**

> 「词向量」这一项要单独说明：它用共现矩阵 + PPMI + SVD 从你自己的语料里学
> 「哪些词总一起出现」，不需要任何预训练模型。但实测接进检索重排后
> **top1 相关率 86% → 86%，没有提升**（语料太小，而且会把「关键词 / 键词」
> 这种字符重叠当成语义相近）。所以它现在只训练、落库、不参与检索。
> 语料涨到几千条以上之后可以回来重新评估。

#### 「按当前内容范围重建」有个坑，必须知道

这个操作会清空事件/摘要并按**当前策略**重新导入。也就是说：

> 把某个工作区设成「不存」之后再重建，那个工作区的历史数据会**消失**。
> 源日志还在硬盘上，但策略不让它入库，重建后就是没有。

所以点按钮时会先把「当前库多少 / 预计保留多少 / 预计丢弃多少」算给你看，
并且**自动先备份一份**（文件名带时间戳）。看到「预计丢弃」不是 0 就停下来想一下。

想只改词、不动内容的话，用「词表 → 重新发现」——它只重算词表、重建索引，
**不碰**原文和摘要。

## 常见任务

### 让某个会话开始被记住

会话页 → 那一行「存」选 **存**。

如果它之前是「不存」，历史内容会被**重新读取一遍**（水位清零），不是只记之后的。

### 让某个会话能查以前的记忆

会话页 → 那一行「读」选 **全库**（或「仅本会话」/「标签：xxx」）。

### 让几个会话共享记忆

1. 给这几个会话都加上同一个标签（比如 `项目A`）
2. 在其中一个会话的「读」里选 `标签：项目A`
3. 想同时读多个标签：进入标签模式后再点行里出现的其他标签

### 钉住一段重要对话

置顶页 → 选会话 → 来源「消息」→ 点住起点、Shift+点终点 → 填标题 → 模式选「常驻」→ 置顶。

### 钉一个结论（整条摘要）

置顶页 → 选会话 → 来源「整条摘要」→ 点一条 → 置顶。

### 确认联想真的生效了

「联想」页看最近几条记录：**注入**列是 +N 就说明联想起作用了。

想立刻验证：发一句和旧事相关的话（比如"上次那个 bug 是什么原因"），再回「联想」页刷新 —— 应该多一行，且命中里有编号。

也可以直接问我「你刚才联想到了什么」，我能看到注入的内容并复述。

### 换个磁盘放记忆库

运维页 → 数据目录，填新路径 → 「迁移」。

**默认放在哪**：不用你操心。第一次运行会自动挑一个非系统盘（D/E/F/G 里剩余空间 ≥ 2 GB 的），选定后就记住，以后一直用那个。这样做是因为记忆库只增不删，会长到 GB 级，压在系统盘上迟早出问题。

万一自动选的位置不满意，用上面那个「迁移」换掉就行。

会**复制**整个目录、逐表校验行数，校验通过才切换；失败自动回滚。迁移成功后会在 `DSH_HOME` 写一个位置指针，重启后自动用新目录（不需要再改配置）。

### 只保留对话、不要工具输出（或反过来）

设置里的 `storeToolCall` / `storeToolResult` 控制**归档层**要不要存工具内容；
摘要和关键词**永远只取对话**，这一点不受配置影响。

改完之后到运维页点一次「按当前内容范围重建」，老摘要才会按新规则重算。

### 联想太吵（老是想到不相关的事）

先看「联想」页的**「展开 → 为什么」**（0.6.0 起），再决定改什么：

1. **看「分数构成」里的扩散**：如果一条摘要的 `扩散` 占比明显大于 `词命中`，
   说明它是通过共现词"蹭"进来的，不是真命中。这种情况屏蔽词没用，调阈值才有用
2. **看「被挡掉」**：如果该参与的词被挡了，是词库问题，不是阈值问题
3. 反复出现同一条明显不相关的摘要 → 到**关键词**页把里面的高频词屏蔽掉（mute）
4. 或者把 `hintThreshold` 调高（默认 0.35，调到 0.5 更严格、更容易「宁可不说」）
5. 已经内置了**长摘要降权**：正文越长的摘要系数越低（3000 字约 ×0.55），
   因为长摘要词多面广，天然容易蹭上任何查询。面板上的「长度降权 ×0.xx」就是这个系数

反过来，如果觉得太安静、该联想到的没联想到，把 `hintThreshold` 调到 0.25 试试。

#### 怎么判断「改了之后到底有没有变好」

**感觉不算数。** 仓库里有一份人工标注的基准（17 条真实查询，逐条判过相关性）：

```bash
node scripts/eval-recall.mjs --verbose
```

> 这个脚本只在**源码仓库**里（不在 `.tgz` 安装包里，`files` 白名单没包含 `scripts/`）。
> 从 Releases 装的用户跑不了，需要 clone 仓库。

输出类似：

```
联想质量评估（基准 17 条）
────────────────────────────────────────
top1 相关率       41.2%   (7/17)
top3 命中相关率    37.5%   (18/48)
```

**41.2% 是真实水平**，不是"效果好"。之前文档里如果出现过 86% 之类的数字，
那是用「正文里含几个查询词」判的——那个口径衡量的是词面重叠，太宽松，已经不作为依据。

改检索逻辑（阈值、降权、分词、词表）之后跑一遍，对比这个数字。

已知的失败模式（基准里有具体例子）：

| 模式 | 例子 | 现状 |
|---|---|---|
| 泛查询 | 「我需要操作什么」「做吧按照b方案」 | 无解，本身没有可检索语义 |
| 特定名词查不到 | 问 obsidian 关键词，3 条全无关 | 诊断面板会显示「词库里没有」 |
| 话题漂移 | 问「为什么还显示 C 盘」→ 命中「联想 tab」 | 词法检索的固有局限，见下 |

#### 为什么「只用关键词、去掉 bigram」行不通

这是个很自然的想法：既然 bigram 碎片（「会话」「有关」「大部」）是噪声，那把
它们去掉、只留词表里的真词，检索不就准了？

**实测：top1 相关率从 41.2% 掉到 14.3%，3 条查询直接变成零结果。**

原因是真词表里那 343 个词**全是高频泛词**：

```
记忆 1008 · 文件 914 · 关键词 604 · 用户 517 · 会话 454 · 规则 426
插件 385 · 数据 362 · 人格卡 329 · 备份 303 · 日志 287 · 目录 278
```

用它们检索等于**拿最泛的词去搜**，命中一堆「提到过这些常见词」的摘要。

而真正能定位话题的词，恰恰不在真词表里：

| 词 | 为什么没进词表 |
|---|---|
| `obsidian` | ASCII 词，词发现只处理中文 |
| `c盘` | 中英混合、频次低于门槛 |
| `surfcore` | ASCII 词 |

**所以 bigram 碎片不是纯噪声，它们是区分度的来源。** 它们能抓到「obsidian
这个词出现在这条摘要里」这种精确信号 —— 去掉就等于把唯一的定位能力扔了。

同样的结论也适用于「调整词权重」的各种方案（抬高技术词、压低碎片词），
四种改法全试过，全部无效或有害，详见 CHANGELOG 的 0.6.1。

**结论：话题漂移在纯词法检索框架内已经调到头了。** 想再往上只能换匹配方式
（语义/embedding），而那条路实测也没有提升（见 0.5.3）。

### 改了位置但重启后还在老地方

先看概览页底部的实际路径。如果和你想的不一样：

1. 检查配置里有没有显式写 dataDir（配置优先级最高）
2. 看 ~/.dsh/session-vault-location.json 里的 dataDir —— 这是「上次选定的位置」
3. 都没有才会自动探测

0.4.11 之前有个 bug：defaults() 把 C 盘填进了配置，导致位置指针和自动探测被永久跳过，改了也没用。升级到 0.4.11 之后修复。

### 彻底清空重来

运维页 → 「全部关掉」清策略；想连数据也清就点「按当前内容范围重建」（重建会重新导入，数据不会丢，因为原始会话日志在 DSH 自己那儿）。

## 模型会自动做的事

1. **每轮开始**（`agent/inbox/claimed`）：
   - 算置顶：按当前会话的读策略，挑出要注入的置顶，放进系统提示的 `session-vault:pins` 段（order 0.71）
   - 算联想：分词 → 关键词门控 → 挑出相关摘要，放进 `session-vault:hint` 段（order 0.73），只给标题和 id，不给正文
2. **常驻边界声明**：系统提示里有一句"记忆库的边界"（可关）
3. **定时扫描**：默认每 300 秒扫一次新内容（`scanIntervalSec`，0 = 关）
4. **启动扫描**：启动 8 秒后扫一次（错开宿主自己的加载高峰）

子智能体（subagent）**不注入**记忆，避免污染。

## 常用配置

设置 → 记忆库 → 配置（38 项，列常用的）。

| 配置 | 默认 | 说明 |
|---|---|---|
| `dataDir` | 空 = 自动选择 | 数据目录。留空时第一次运行会探测：优先非系统盘（D/E/F/G，剩余 ≥ 2 GB），都没有则回退 `<DSH_HOME>/session-vault`，选定后记住不再变。改这里**不会搬文件**，用运维页的迁移 |
| `autoHint` | 开 | 每轮自动联想 |
| `hintThreshold` | 0.35 | 联想触发阈值，越高越严格 |
| `hintMaxItems` | 3 | 最多提示几条 |
| `hintCooldownMin` | 10 | 同一条多少分钟内不重复提示 |
| `pinBudget` | 1500 | 置顶每轮最多注入多少字 |
| `pinHitThreshold` | 0.35 | 置顶「按需命中」的阈值 |
| `storeUser` / `storeAssistant` | 开 | 存对话 |
| `storeToolCall` / `storeToolResult` | 开 | 存工具内容（只进归档层） |
| `storeSystem` / `storeDeveloper` / `storeReasoning` | 关 | 注入内容和思考过程不存 |
| `scanIntervalSec` | 300 | 定时扫描间隔，0 = 关 |
| `vectorTrainIntervalSec` | 21600 | 词向量重训间隔（6 小时），0 = 关。**这些向量不参与检索** |
| `termMinDf` | 2 | 关键词最小出现次数 |
| `debug` | 关 | 打开后写详细日志 |

## 排障

**设置页里没有「记忆库」这一栏**
客户端 bundle 没加载起来。按 F12 看控制台有没有 `session-vault` 的报错。宿主日志不会告诉你根因。

**启动变慢**
重启后看日志有没有 `[session-vault] 插件初始化耗时 xxx ms`。有的话是插件的问题，把数字记下来。

**关键词里全是没意义的词**
先看「全部」还是「只看中文」；再用「看哪个会话」定位。单个没用的词可以点屏蔽。

**搜不到东西**
- `memory_recall` 走记忆层（摘要），只覆盖对话
- 工具输出用 `memory_search`
- 还要确认那个会话的「读」不是「关」

**迁移后重启又回到旧目录**
迁移成功后应该自动记住新路径（`<DSH_HOME>/session-vault-location.json`）。如果还是旧的，检查这个指针文件是否存在、内容对不对。

**改了内容范围，但关键词还是旧的**
到运维页点「按当前内容范围重建」。
